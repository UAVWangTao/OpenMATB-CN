## 场景语法

场景文件必须放在 **`includes/scenarios/`** 目录下。要在启动 OpenMATB 时执行某个场景，需在 **`config.ini`** 的 `scenario_path` 参数中填写**相对于 `includes/scenarios/` 的路径**（可含子文件夹）。例如：

```ini
scenario_path = myexperiment/scenario_1.txt
```

启动后程序会读取该场景；若存在错误，会显示在界面中，并写入 **`last_scenario_errors.log`**。之后实验中的事件都按该场景文件中的**命令行**依次处理。

例如下面这段场景：

```
0:00:00;sysmon;start
0:00:10;sysmon;scales-1-side;1
0:00:10;sysmon;scales-1-failure;True
0:00:30;sysmon;lights-2-failure;True
0:00:50;sysmon;stop
```

含义依次为：

1. 在实验开始（`0:00:00`）启动系统监控任务（`sysmon`）；
2. 第 10 秒将第一块刻度偏向一侧（`scales-1-side;1`），并触发该刻度故障（`scales-1-failure;True`）；
3. 第 30 秒触发第二盏灯的故障（参数名以你使用的 `sysmon` 版本为准，如 `lights-2-failure`）；
4. 第 50 秒停止系统监控任务。

除**空行**和以 **`#`** 开头的注释行外，每一行至少包含三部分，用**分号**分隔：

```text
时间;插件别名;命令
```

---

## 时间

时间写在最前面，格式为 **`H:mm:ss`**（小时:分钟:秒），表示从实验开始算起，**何时触发**该命令。

---

## 插件别名

中间一段是**插件别名**，指明命令发给哪个插件。常见别名如下：

| 别名 | 说明 |
|------|------|
| **`sysmon`** | 系统监控：六块仪表，检测异常并按键纠正 |
| **`track`** | 跟踪：用操纵杆补偿十字准星漂移 |
| **`scheduling`** | 调度：显示各任务手动/自动与时间安排 |
| **`communications`** | 通讯：语音指令，调节无线电频率等 |
| **`resman`** | 资源管理：油罐与油泵，维持目标液位 |
| **`performance`** | 绩效：向被试显示当前综合绩效水平 |
| **`instructions`** | 说明：全屏显示说明（内容来自 `includes/instructions/` 中文本） |
| **`genericscales`** | 通用量表：问卷（内容来自 `includes/questionnaires/` 中文本） |
| **`labstreaminglayer`** | LSL：通过网络用 LSL 协议输出标记与日志 |
| **`parallelport`** | 并行口：通过物理并口发送标记 |

## 命令

时间与插件确定后，需要写出**具体命令**。命令分两类：**动作（Actions）** 与 **参数（Parameters）**。

### 动作（Actions）

动作用于向插件发送“信号”，例如在某个时刻让资源管理任务**暂停**：

```
0:05:30;resman;pause
```

常用动作包括 **`start`**、**`stop`**、**`pause`**、**`resume`**、**`show`**、**`hide`** 等（以各插件实际实现为准）。若某任务从未 **`start`**，界面上不会出现该任务；已 **`start`** 的任务一般应在场景结束前 **`stop`**。

**说明 1：** 有些插件在被试完成后会**自动停止**（如 `instructions`、`genericscales`）。

**说明 2：** 收到动作命令时，程序会调用对应插件 Python 文件中的同名方法（例如 `resman;pause` 会执行 `resman` 插件里的 `pause()`）。

### 参数（Parameters）

参数用于修改插件的**内部状态**，可在插件**尚未 start** 时设置。命令通常分为两段：`参数名;值`。

示例：在第 10 秒让系统监控第一块刻度进入故障：

```
0:00:10;sysmon;scales-1-failure;True
```

这里 `scales-1-failure` 表示要修改 **`scales`** 中编号 **`1`** 的 **`failure`** 参数；层级用**连字符**连接，与插件代码里 `sysmon.py` 等文件中的字典结构一致。

若参数不属于嵌套结构，可直接写参数名，例如：

```
0:00:10;sysmon;alerttimeout;2000
```

各任务有哪些参数、可取哪些值，请以仓库中的 **`parameters.csv`** 及对应插件源码为准；官方 Wiki 也提到有完整参数说明可供查阅。

## 推荐的场景文件结构

程序会按**时间**对所有命令排序后再执行，因此行在文件中的先后顺序可以不完全按时间排列；但为便于阅读和维护，建议按下面结构组织（多用 `#` 注释分段）：

```text
# 场景标题
# 说明注释

# 1. 设置各任务参数
# 1.a. 系统监控
# 1.b. 资源管理
# 1.c. 跟踪
# 1.d. 通讯

# 2. 启动需要使用的任务

# 3. 实验过程中的事件

# 3.a. 系统监控相关事件
# 3.b. 资源管理相关事件
# 3.c. 跟踪相关事件
# 3.d. 通讯相关事件

# 4. 结束任务（stop）
```

### 延迟某任务出现时间

若希望某任务在例如 **2 分钟** 才开始，仍建议在 **`0:00:00`** 先 **`start`**，再立刻 **`pause`** 并 **`hide`**，到目标时刻再 **`resume`** 和 **`show`**：

```text
# 2. 启动任务（示例：sysmon 在 2 分钟时才真正出现）
0:00:00;sysmon;start
0:00:00;resman;start
0:00:00;sysmon;pause
0:00:00;sysmon;hide

# 3. 事件……

# 在 0:02:00 恢复 sysmon 显示
0:02:00;sysmon;resume
0:02:00;sysmon;show

# 4. 结束
0:xx:xx;sysmon;stop
0:xx:xx;resman;stop
```

（注意：时间与插件之间、命令各部分之间均使用**英文分号 `;`**，不要使用冒号。）

## 示例（1 分钟场景）

下面与官方 Wiki 中的 1 分钟模板一致，可直接作为参考；你本地的 `basic.txt` 可能与此略有差异，以实际文件为准。

```text
# Scenario template
# Durations are expressed in milliseconds
# Timestamps are stated in the following format H:MM:SS

# 1. Set tasks parameters

# 1.a. System monitoring parameters
# Disable sysmon feedbacks
0:00:00;sysmon;feedbacks-positive-active;False
0:00:00;sysmon;feedbacks-negative-active;False

# 1.b.i. Resources management parameters
# Change tank B target in resman
0:00:00;resman;tank-b-target;1000


# 1.c. Tracking parameters
# Change tracking cursor color
0:00:00;track;cursorcolor;#009900

# 1.d. Communications parameters
0:00:00;communications;callsignregex;[A-Z][A-Z]\d\d
0:00:00;communications;othercallsignnumber;5
0:00:00;communications;voicegender;female
0:00:00;communications;voiceidiom;chinese


# 2. Start appropriate tasks
0:00:00;resman;start
0:00:00;track;start
0:00:00;sysmon;start
0:00:00;scheduling;start
0:00:00;communications;start


# 3. Set scenario events
# Display a NASA-TLX questionnaire

0:00:00;genericscales;filename;nasatlx_fr.txt
0:00:00;genericscales;start


# 3.a. System monitoring events
0:00:10;sysmon;scales-1-side;-1
0:00:10;sysmon;scales-1-failure;True
0:00:30;sysmon;scales-4-side;1
0:00:30;sysmon;scales-4-failure;True

# 3.b. Resources management events
0:00:00;resman;automaticsolver;True
0:00:15;resman;pump-3-state;failure
0:00:25;resman;pump-3-state;off
0:00:25;resman;automaticsolver;False
0:00:30;resman;pump-7-state;failure
0:00:40;resman;pump-7-state;off

# 3.c. Tracking events
0:00:20;track;automaticsolver;True
0:00:40;track;automaticsolver;False


# 3.d. Communications events
# 注意：两条语音之间要留足间隔，避免声音重叠
0:00:00;communications;radioprompt;own
0:00:25;communications;radioprompt;other
0:00:40;communications;automaticsolver;True
0:00:45;communications;radioprompt;own


# 4. End tasks at 1 minute
0:01:00;resman;stop
0:01:00;track;stop
0:01:00;sysmon;stop
0:01:00;communications;stop
0:01:00;scheduling;stop
```
